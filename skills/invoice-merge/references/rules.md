# 材料分类与拼版规则

这些规则决定了输出长什么样，也是 `--dry-run` 里要核对的东西。`--help` 不会讲这些。

## 五个类别

按报销业务顺序排列（`--no-organize` 可关掉重排）：

| 顺序 | 类别 | 识别依据（文件名 + 正文前 3 页一起看） | 排版 |
| --- | --- | --- | --- |
| 1 | 酒店发票 | 酒店 / 宾馆 / 旅店 / 民宿 / 客房 / 住宿 / 入住 / 房费 / 饭店 | 两张一页，不旋转 |
| 2 | 差旅费报销单 | 差旅费报销单 / 差旅报销单 / 报销单 / 报销审批单 | 独占整页 |
| 3 | 火车 / 飞机票据 | 机票 / 飞机票 / 登机 / 航班 / 行程单（电子发票版）/ 客票 / 火车 / 高铁 / 动车 / 铁路 / 12306 | 两张一页，不旋转 |
| 4 | 其他材料 | 上面都不匹配，以及下面的前置规则；**全部图片文件**（不看文件名） | 三张一页，竖版的转 90°，同小类的挨在一起 |
| 5 | 票据粘贴单封面 | 票据粘贴单 / 粘贴单 / 凭证封面 / 报销封面 / 封面 | 独占整页 |

## 五条前置规则（优先级最高，容易判错就错在这里）

1. **结账单、宾客水单不是酒店发票。** 它们是酒店 / 平台出具的消费流水，不是税务发票
   → 归「其他材料」。关键词：结账单 / 结帐单 / 消费明细 / 账单明细 / 水单。
   带"发票"字样的文件除外，避免把"某某结账单发票"这类真发票误伤。
   水单正文里几乎一定写着酒店名，所以这条必须先于"酒店"关键词判定，否则会挤进
   酒店发票那一摞，把酒店发票最后没排满的半页占掉。
2. **行程校验单不是机票。** 它是航旅纵横这类平台出具的验真行程信息单（姓名、航段、
   票号、含税价），没有税务发票要素 → 归「其他材料」。关键词：行程校验 / 校验单。
   真正的机票发票是「电子发票（航空运输电子客票行程单）」，带发票号码与民航发展基金。
   带"发票"字样的文件除外（发票与校验单合订成一份 PDF 时按票据算）。
   这条必须早于"机票"这个交通关键词命中 —— 校验单文件名里通常就带着"机票"。
3. **电子登机凭证、登机牌不是交通票据。** 它们是乘机时打印的整页 A4 纸 → 归「其他材料」，
   好和结账单、审批单一起三张一转。必须早于"登机"这个交通关键词命中。
4. **出差申请审批单是流程单据** → 归「其他材料」。关键词：出差申请 / 出差审批。
5. **图片不是发票，一律归「其他材料」。** 图片没有文本层，关键词无从判断，按随附材料处理最稳妥：
   文件名里带「酒店」「机票」也不改类，固定落在第 4 位。支持 `.jpg` `.jpeg` `.png` `.bmp`
   `.tif` `.tiff` `.webp` `.gif` `.heic` `.heif`；HEIC / WebP 需要转换器（macOS 自带 `sips`；
   Windows / Linux 装 Pillow + pillow-heif 或 ImageMagick），一个都没有时提示先转格式。

用户说"这张归错类了"时，先跑 `--dry-run` 看 `命中「…」` 那一列，再判断是被哪条规则抓走的。

## 「其他材料」内部的小类归拢

其他材料里什么都有，直接按文件顺序排会把同一摞拆散（05 校验单、06 截图、15 校验单…），
贴票时来回翻。所以这类材料在排序时再切一层小类，同类的挨在一起：

| 小类 | 判据（文件名优先，其次看分类时命中的关键词） |
| --- | --- |
| 消费明细 | 水单 / 结账单 / 结帐单 / 消费明细 / 账单 / 明细 |
| 行程校验单 | 校验单 / 行程校验 |
| 出差审批单 | 出差审批 / 出差申请 / 审批单 |
| 登机凭证 | 登机凭证 / 登机牌 / boarding |
| 订单截图 | 订单 / 截图 / 待支付 / 购票 |
| 其他材料 | 都不匹配时用它兜底 |

- 摞与摞之间按**首次出现的先后**排，摞内保持用户选的排序。
- 拼版时一摞若能放进当前纸剩下的条带，就顺着排；放不下就整摞挪到下一页，
  不把同一摞拆到两张纸上（除非这一摞本身超过一页的容量）。

## 拼版（band 排版）

- 一张 A4 纵向纸按纵向等分成若干条带，每张材料占一条，**内容完整保留**，放不下才整体缩小 ——
  绝不按页高硬切，那会把"价税合计"那几行切掉（历史上真出过这个 bug）。
- 每张材料先按实际墨迹范围去掉四周空白，再决定摆法。「其他材料」会在"横过来"和"正着放"
  之间自动取成像更大的那个；A4 竖版单据横过来比硬竖着塞大约成像一成半。
- 内容顶部统一朝右（旋转 270°），与差旅费报销单、封面那套单页旋转的摆向一致，
  整本材料翻看不用来回换手。
- 相邻两份材料之间画一条灰色裁切虚线，内容四周各留 6 毫米，虚线上下共 12 毫米净空，
  沿线下剪子碰不到字。
- **不同类别不混排**在同一张纸上。
- 「其他材料」不足三张时按实际张数分带；只剩一张则独占整页、不缩小。
- **图片就是一张一页的材料**：和其他材料共用条带与裁切虚线，竖版图片同样可转 90° 横躺；
  图片的 EXIF 方向由 PyMuPDF 自动应用，手机竖拍的照片不会转歪。
- **`--size keep` 下拼版不生效**：拼版必然要重绘并统一到一张纸，与"逐页原样复制"冲突。
  此时每张图片独占一页，按图片 DPI 元数据换算成 pt 保持原始尺寸，不重采样；
  超 A4 的图片（手机原图常见 1.4 米宽）按 A4 上限等比缩小，只缩不放。

## 扫描件

默认在写盘前把整份输出重组成扫描件：每页一张 300dpi 整页 RGB 图片。

- 结果：**没有文字层，不能选中、不能搜索**，等同打印出去再扫回来。
- 页面尺寸不变（A4 仍是 595.3 x 841.9 pt），只是内容的表示方式换了。
- 代价：8 页约 3.4 MB、多花 1～2 秒。`--scan-dpi 150` 体积约省一半，小字会开始发虚。
- 要矢量原件（保留文字层）加 `--no-scan`。
- 图片页同样整页转成 300dpi 扫描图；不想二次栅格化就加 `--no-scan`。
- 判断是否真的转成了扫描件：`页数` 不变，但每页 `get_text()` 应为空、`get_images()` 应为 1 张。
